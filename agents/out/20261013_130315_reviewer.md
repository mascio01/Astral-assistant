# Report REVIEWER — Astral

## 1. Bug / regressioni probabili

- **`tools_lights.py` mancante** (`FileNotFoundError`). Se è referenziato da altri moduli, l'import fallirà a runtime. Verificare se è una rimozione voluta o una regressione.
- **File troncati** (`stt_integration.py` si interrompe su `if os`, `roles.py` su `max_tok`): impossibile validare il `finally` di cleanup del WAV temporaneo e la chiamata LLM finale. Da riproporre completi.
- **`roles.py`**: `r["tools"]` e `r["descrizione"]` acceduti con `[]` — `KeyError` se il ruolo è mal configurato in `jobspec`. Usare `.get()`.
- **Fallback modello hardcoded** `"deepseek/deepseek-v4-flash-0731"`: se il nome non esiste più, ogni errore di routing degrada silenziosamente su un modello inesistente.
- **`stt_integration.py`**: `_tmp_mic.wav` in `WHISPER_DIR` senza lock → race condition con invocazioni concorrenti. `--no-speech-thold` non è un flag standard di `whisper-cli` recente (verificare versione bin); se errato, `subprocess.run` fallisce e ritorna `None` mascherando il problema.
- **`elapsed += 0.1`** in `_record` assume blocchi da 0.1 s esatti: con underrun di `sounddevice` il timeout reale può sforare `MAX_SECONDS`.

## 2. Rischi sicurezza

- **SSRF TOCTOU / DNS rebinding** in `validate_url`: la risoluzione avviene in `getaddrinfo`, ma `httpx` ri-risolve al fetch. Un attaccante con DNS a TTL 0 può far passare la validazione su IP pubblico e connettersi a `127.0.0.1`. Mitigazione: pinnare l'IP risolto (custom transport / `resolver`) o usare `httpx` con IP esplicito + `Host` header.
- **Bypass IPv4-mapped IPv6**: `ipaddress.ip_address("::ffff:127.0.0.1").is_loopback` è `False` su molte versioni Python → loopback raggiungibile. Aggiungere check `ip.ipv4_mapped` (3.13+) o normalizzare.
- **Redirect**: il commento afferma che la guardia va invocata anche sui redirect, ma il codice mostrato non lo dimostra. Se `httpx` segue redirect di default senza re-validazione, la protezione è aggirabile.
- **`_read_file_rel`**: confinamento corretto (`realpath` + prefisso), ma `contesto` arriva dal LLM: un prompt injection può enumerare file sensibili dentro il repo (`.env`, chiavi). Valutare allowlist esplicita.
- **`log_error`** scrive traceback completi su disco: possibile leak di path/segreti in log condivisi.

## 3. Verdict

**RIFIUTA CON RISERVA** — La guardia SSRF è un buon inizio ma incompleta (TOCTOU, IPv4-mapped, redirect non verificati); file troncati e `tools_lights.py` mancante impediscono la validazione end-to-end. Da riproporre completi con IP pinning e allowlist di contesto.
